02 列表与正文

分类决定"抓哪个地址",这里决定"从抓回来的东西里取出什么"。

列表:先找"每一项"

ruleArticles 指向的是单条记录的容器,不是整个列表。

ruleArticles: class.feed@tag.item

然后逐字段取,规则作用在每一条上:

  • ruleTitle —— 标题;
  • ruleLink —— 文章地址(相对地址会自动绝对化);
  • rulePubDate —— 时间;
  • ruleDescription —— 摘要;
  • ruleImage —— 封面。

是 RSS / Atom 就不用写规则

ruleArticles 留空时,软件按标准 RSS / Atom 解析 item 与 entry,标题、链接、时间、摘要都是现成的。只有当站点返回的是普通网页或私有 JSON 时才需要自己写。

翻页

两种形态,别写混:

  • 有"下一页"链接 —— ruleNextPage: text.下一页@href;
  • 靠页码 —— ruleNextPage: PAGE,页码由分类地址里的 {{page}} 提供。

把"下一页"写成当前页地址,会去请求同一页,结果是文章全被去重、看起来"只有一页"。这是最常见的翻页错误。

正文

ruleContent: class.article-content@html

@html 保留标签(图片、段落都在),@text 只留文字。要保留排版就用 @html。

正文里的相对图片与链接会按文章地址绝对化,不用自己拼。

正文需要跑脚本怎么办

如果正文里带 <script> 且真的发请求(播放器、懒加载),软件会把它放进一个有真实站点源的容器里跑。这不是你能开关的,是自动判断的 —— 所以规则只要把 HTML 原样取出来即可,不要提前把 <script> 删掉。

自检

  • 列表能出条目,但点进去是空的 → 先看 ruleContent 是不是取到了容器内层;
  • 条目重复 → 列表规则取到的是外层容器;
  • 第二页和第一页一样 → 翻页规则写错了(见上)。
