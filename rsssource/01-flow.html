01 解析流程:先看有没有列表规则

订阅源的判断只有一个岔路口:ruleArticles 空不空。空的就是标准 RSS,软件用默认规则拆;不空的就按你写的规则拆。这一步决定了后面所有事。

一次订阅的完整顺序

  1. 请求 sourceUrl(分类里点了某个分类时,请求的是分类的地址);
  2. 看 ruleArticles:
    • 空 → 当成标准 RSS/Atom,用默认字段映射解析;
    • 不空 → 用这条规则切出"每一篇文章";
  3. 再对每一篇取 ruleTitle / rulePubDate / ruleImage / ruleLink;
  4. 看 ruleDescription:有就取列表页上的摘要;
  5. 看 ruleContent:有就取正文,没有就打开原网页。

由此分成三种源

① 标准 RSS:只填名称和地址

{ "sourceUrl": "https://example.com/feed.xml", "sourceName": "某站 RSS" }

绝大多数 RSS/Atom 都属于这一档。规则一个都不用写,写了反而可能把默认行为顶掉。

② 有列表 + 有描述

站点没有 RSS,但列表页上"标题 + 摘要"都齐了。列表页直接当订阅源用,点进去打开原网页。

"ruleArticles": "class.post-list@tag.li",
"ruleTitle": "tag.a@text",
"ruleLink": "tag.a@href",
"ruleDescription": "class.excerpt@text"

③ 有列表、没有描述

同上,只是列表页太素。补一条 ruleContent 就能在软件里直接读:

"ruleArticles": "class.post-list@tag.li",
"ruleTitle": "tag.a@text",
"ruleLink": "tag.a@href",
"ruleContent": "content@html"

分类:sortUrl

一行一个分类,格式是 分类名::地址:

"sortUrl": "最新::https://example.com/latest\n热榜::https://example.com/hot"

分类不是写死的、要先请求接口才拿得到时,sortUrl 整段写成 @js:,返回同样格式的多行字符串。分类地址里可以带 {{page}}。

翻页:ruleNextPage

有两个含义,别混:

  • 写成一个地址规则(如 class.next@href)—— 从列表页里取"下一页"的链接;
  • 写成字面量 PAGE —— 表示"按 sortUrl 里的 {{page}} 翻页",软件把页码加一重发。

两者都返回空就走到底了。

单 url 源

整个站的内容就在一个页面上(或者你想把某一页当"订阅"读)。把 singleUrl 设成 true,再加上 loadWithBaseUrl,软件会用内置浏览器把这一页整个加载出来当文章读 —— 页面自己的脚本照跑,视频也能播。

这一档不解析列表,所以 ruleArticles 之类都不需要。

排查顺序

  1. 在浏览器里直接打开 sourceUrl —— 返回的是 RSS 还是网页;
  2. 如果是网页却把 ruleArticles 留空,那会被当成坏的 RSS,列表一定是空的;
  3. 列表有但点进去空白 → 看 ruleLink 取的是不是正文地址;
  4. 分类条不出现 → 看 sortUrl 的格式(冒号是不是全角、有没有换行)。
