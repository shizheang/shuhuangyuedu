03 单 url 源

有一类站点没有"文章列表" —— 整个站就是一个会自己滚动的页面(论坛、资源导航、聚合页)。这类不要硬写列表规则,用单 url 那一档。

怎么声明

singleUrl: true
sortUrl: 默认::https://example.com/

打开源之后,软件直接把那个地址作为一个完整页面呈现,不解析列表、不解析正文。

它和普通源的区别

  • 不需要 ruleArticles / ruleContent;
  • 顶栏只有一个"重新加载",没有分类栏(除非你写了多个 sortUrl 条目);
  • ruleContent 留空时才走这一档 —— 写了正文规则就不是单 url 源了。

三种呈现方式,由软件自动选

  1. 直接把这个地址嵌进来(最忠实:相对地址、同源 cookie、站点脚本全都正常);
  2. 站点声明了"不许被内嵌"时,由软件代取 HTML 再呈现(站内跳转仍可用);
  3. 前两种都失败时,给一个明确的出口 —— 用独立窗口打开。

所以写单 url 源时不需要为"能不能嵌"做任何处理,软件会先探测再决定。

什么时候不该用它

  • 站点有真正的文章列表 —— 用普通订阅源,能拿到标题、时间、摘要,体验好得多;
  • 你只想要站点的某一块内容 —— 那还是写 ruleContent。
