五种模式:靠前缀选

规则串的第一件事是决定用哪种解析器。前缀写了就用哪种,没写就看内容猜(以 $. 开头当 JSONPath、以 / 开头当 XPath、其余当默认规则)。选错不会报错,只会取到空 —— 而空和「这一页本来就没有」在界面上长得一样。

模式前缀用在哪
默认规则不写,或显式写 @@HTML 页面,最常用
CSS@css:标准 CSS 选择器,网上搜到的现成选择器能直接用
JSONPath@Json:,或直接以 $. / $[ 开头接口返回 JSON
XPath@XPath:,或直接以 / / // 开头HTML 与 XML 都行
JS@js:,或整段写成 <js>…</js>要计算、拼接、按条件分支

默认规则

按 @ 分段,前几段选节点,最后一段取值。每段是 类型.名称.位置。

class.book-list.0@tag.li@tag.a@href
  • 类型:class / id / tag / text(按包含的文字找)、children(所有子标签,写法 children[1]);
  • 位置从 0 开始,不写就是全部,-1 是倒数第一个;
  • 位置还能排除:!0:2 表示「排除第 0 与第 2 个」;
  • 取值:@text、@html(内层 HTML)、@ownText(只取直属文字)、@textNodes、@all(含标签本身),以及任意属性名 @href / @src / @data-id。

列表规则取的是「每一项」:class.result-list@class.result-item 得到的是一串条目,后面每条字段规则都在单个条目里跑,所以字段不用再写容器。⚠️ 容器与每一项同标签时别用 @tag.div —— 容器自己会被算成一项。

CSS 与 XPath

@css:.book-list li a@href
@XPath://div[@id='content']//p//text()

两种都是标准写法,能用在网上搜到的现成选择器。CSS 后面同样可以用 @ 继续取值;XPath 一般直接取到文本(//text())或属性(//@href)。

JSONPath

$.data.list[*]        → 列表:取数组里的每一项
$.data.list[0].title  → 单个字段
$..title              → 任意层级的 title

列表规则取 $.data.list[*],字段规则只写 $.title —— 与默认规则同一个道理:字段是在单个条目里跑的。

JS:@js: 与 <js>

@js: 只能放在最后一段;要拿前面规则的结果,用变量 result。整段 JS 里最后一条产生值的语句就是规则结果。

@js:result.split('\n').filter(x => x.trim()).join('\n')

<js>…</js> 可以放在任意位置,还能当分隔符用:tag.li<js></js>//a。

正则替换:##正则##替换

跟在别的规则后面,把结果里的匹配项循环替换掉。第二段留空就是删除。

class.author@text##作者：##
id.content@html##<br\s*/?>##\n

三个连接符

只用于同一类规则之间(不跨 JS 与正则):

符号含义
&&全部取到并合并
||取第一个有结果的(最常用:一个字段好几个备选位置)
%%依次交错取:三个列表的 1、2、3 各取第一个,再取第二个……

把中间结果存起来:@put: 与 @get:

同一个请求要复用几次时就别取三遍:

https://api.example.com/view?aid={{$.id}}@put:{"cid":"$.cid"}

@put: 把后面几个子规则的结果存进变量表,后面的规则用 @get:{cid} 取。它在同一次请求的那条规则链里有效。

在规则里插值:{{}}

在搜索地址 / 发现地址里,{{}} 里只当 JS 写({{key}}、{{page}}、{{(page-1)*20}});在其它位置的 {{}} 里可以写任意规则,但要带类型前缀({{@@class.x@text}}、{{$.title}})。

列表反序

整条列表规则前面加一个 - 就把顺序倒过来 —— 有些站的目录是倒着排的:

-id.chapter-list@tag.li
