04 加密:摘要、HMAC 与对称加解密

这些方法都是同步的,可以直接写在规则里。密钥和 IV 传字符串或字节数组都行 —— 但两者的含义不同,下面分开说。

摘要

  • java.md5Encode(str) —— 32 位小写 MD5;
  • java.md5Encode16(str) —— 取上面那 32 位里的中间 16 位;
  • java.sha256Hex(str) / java.digestHex(str, 'SHA-256') —— SHA-256。

摘要按 UTF-8 字节算。中文关键词不会因为编码不同而和服务端对不上。

HMAC

java.HMacHex(data, 'HmacMD5', key)
java.HMacHex(data, 'HmacSHA256', key)

参数顺序是 (数据, 算法, 密钥),返回十六进制小写串。算法名大小写与连字符不敏感。目前只支持 MD5 与 SHA-256,用了别的会当场报错,而不是悄悄给你空串。

对称加密(AES / DES 一类)

var c = java.createSymmetricCrypto('AES/ECB/PKCS7Padding', key, iv);
c.encryptBase64('明文')     // → Base64 密文
c.decryptStr(密文)          // → 明文
c.encryptHex('明文')        // → 十六进制密文

密钥与 IV 的口径,这一条最容易错:

  • 传字符串 —— 取它的 UTF-8 字节当密钥,长度必须是 16 / 24 / 32 字节;
  • 传字节数组(java.strToBytes(s) 或 java.base64DecodeToByteArray(s) 的结果) —— 原样使用,不会再转字符串。

CBC 模式必须给 16 字节 IV;ECB 不需要。长度不对时返回 null,不会抛。

编解码

  • java.base64Encode(s) / java.base64Decode(s)
  • java.strToBytes(s) —— 字符串 → UTF-8 字节;
  • java.base64DecodeToByteArray(s) —— Base64 → 字节;
  • java.encodeURI(s) —— URL 编码(拼进地址的密文必须过一遍)。

排错顺序

  • 先确认密钥长度对不对(16 / 24 / 32)。长度非法时 AES 返回 null,下一步往往是 Cannot read properties of null;
  • 再确认填充方式与站点一致(PKCS5 与 PKCS7 在 AES 下等价);
  • 还不对就比对一个已知答案:拿站点能解开的样例反推是编码问题还是密钥问题。
