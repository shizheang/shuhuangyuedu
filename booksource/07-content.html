07 正文

正文只有一条规则,但它决定了读起来是舒服还是糟心:取 @html 段落才分得开,取 @text 是一整块糊在一起的文字。

最少一行

"ruleContent": { "content": "id.content@html" }

@html 拿到的是内层 HTML,<p> / <br> 都在,阅读页据此断段。@text 只会得到一段没有换行的纯文本 —— 除非站点本来就用换行符分段。

正文被切成好几块

有的站把正文放在相邻的几个容器里(广告位把文章劈开)。用 && 合并:

id.content@html&&id.content-2@html

顺序就是合并顺序。|| 则是"取第一个有结果的" —— 用在同一个正文的几种候选容器上。

正文分页

nextContentUrl 返回下一页正文的地址,空串就停止。软件会一直跟下去再拼成一章:

"nextContentUrl": "class.next-page@href"

正文里的图片

图片地址默认按正文页地址绝对化。需要带请求头(防盗链的站)时,在正文规则里把图片包成带选项的写法:

@js:result.replace(/<img[^>]*src="([^"]+)"[^>]*>/g,
  (_, src) => '<img src="' + src + ',{' + JSON.stringify({ headers: { Referer: baseUrl } }) + '}">')

imageStyle 可以给所有图片统一加上样式;图片本身是加密/扰乱的(imageDecode)属于进阶,先确认不是请求头的问题再说。

净化:正文里混了站点自己的水印

id.content@html##本章未完，请点击下一页##

跟在规则后面的 ##正则##替换 会循环替换。也可以不给正则、只给一段字面量 —— 那是"包含这段就删掉"的简写。全局的净化规则在设置 → 净化规则里,对所有源生效,优先用那个。

需要站点自己的 JS 跑完才有正文

"content": "id.content@html",
"webJs": "@js:..."

webJs 是在内置浏览器里、页面加载完之后才执行的 JS,适合"正文由前端脚本渲染出来"的站。它比普通规则慢得多,只在这条路能通、别的都不行时才用。

读完还是空的,按这个顺序查

  1. 这一章的章节地址对不对(目录取错了链接最常见);
  2. 页面是不是要求登录 / VIP / 付费 —— 会把站点给的提示原样报出来;
  3. 正文容器的 id 是不是每次都变(有些站用 content-{随机}),那就得换成不带随机部分的规则;
  4. 是不是被换了编码 —— 检查源里有没有声明 charset。
