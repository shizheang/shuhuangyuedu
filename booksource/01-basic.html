01 基本:一个源最少要有哪些字段

一个书源就是一段 JSON。下面这份只填了「搜索 → 详情 → 目录 → 正文」四段,已经能读完整的书;其余字段都是可选增强。先让这四段跑通,再回头加别的。不知道这四段从哪来,先看 02 走查。

最小可用的一个源

{
  "bookSourceUrl": "https://example.com",
  "bookSourceName": "示例源",
  "searchUrl": "https://example.com/search?q={{key}}",
  "ruleSearch": {
    "bookList": "class.result-list@tag.li",
    "name": "tag.h3@text",
    "author": "class.author@text",
    "bookUrl": "tag.a@href"
  },
  "ruleBookInfo": { "tocUrl": "class.btn-mulu@href" },
  "ruleToc": {
    "chapterList": "id.list@tag.dd",
    "chapterName": "tag.a@text",
    "chapterUrl": "tag.a@href"
  },
  "ruleContent": { "content": "id.content@html" }
}

这四段的字段名是固定的:ruleSearch、ruleBookInfo、ruleToc、ruleContent;发现页那一段叫 ruleExplore。每一段都是对象,里面再按 name / author 这种键填规则。

源本身的字段

  • bookSourceUrl —— 必填,且唯一。它就是身份:再导入一次同地址的源 = 覆盖,不是新增一条。
  • bookSourceName —— 必填,可以重名。书架换源、搜索结果的"来源"里显示的就是它。
  • bookSourceGroup —— 分组,只影响书源列表怎么归类。
  • bookUrlPattern —— 书名页地址的正则。可不填;填了之后,在浏览器里打开一本书的页面时,本软件才知道"这本书该用哪个源打开"。
  • header —— 访问该站点时统一带上的请求头(JSON)。见 04 地址。
  • loginUrl / loginUi —— 账号型源用。见 08 登录。
  • jsLib —— 一段先于所有规则执行的 JS。远程库(填一个地址)也行,它会在源初始化时被拉下来。
  • variable —— 源自己的一串变量(JSON),规则里用 @get: / {{}} 取。见 10 速查。
  • concurrentRate —— 并发/间隔限制,形如 1/1000(每秒 1 次、间隔 1000 毫秒)。不填就按全局设置。
  • enabledExplore —— 发现页开关。没填 exploreUrl 的源,这一项设 true 也没用。

写完之后怎么验

导入后在源调试页里逐段跑:搜索 → 详情 → 目录 → 正文。哪一段空,就从那一段往前看一页。四个最常见的"空":

  • 返回的是 JSON 却用了 CSS 规则(或反过来)—— 先看原始响应的第一个字符是 < 还是 {;
  • 列表规则取成了"整张表"而不是"每一行" —— 05 搜索与发现 里专门讲这条;
  • 链接是相对地址,而你没让软件去补 —— 默认会按来源页自动补全;
  • 站点要求登录或被墙 —— 那一段会给出请求地址与状态码。
