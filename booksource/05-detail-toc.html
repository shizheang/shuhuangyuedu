05 详情与目录

详情页不是必填的一段:什么都不写,软件会沿用搜索页取到的书名、作者和封面。写它通常是为了拿到目录地址,或者页面上的简介比搜索列表里全。

详情:ruleBookInfo

"ruleBookInfo": {
  "name": "class.book-info@tag.h1@text",
  "author": "class.book-info@class.author@text",
  "intro": "class.intro@html",
  "kind": "class.tags@text",
  "lastChapter": "class.latest@tag.a@text",
  "coverUrl": "class.pic@tag.img@src",
  "wordCount": "class.words@text",
  "tocUrl": "class.btn-mulu@href"
}
  • tocUrl —— 目录页地址。只支持单个地址;不写就认为"这本书的目录和详情在同一个页面上"。
  • canReName —— 规则不为空、且详情页也真取到了书名/作者时,用详情页的覆盖搜索页的。有些站搜索列表里的书名是缩写的,靠它纠正。
  • init —— 预处理。整个详情页只跑一次,结果供上面这些字段用(见下)。

init:先算一次,后面直接取

当详情数据来自一个接口、或者要在一堆脚本里翻 JSON 时,先把它算成对象,后面的字段就只写键名:

"init": "<js>JSON.parse(java.ajax(baseUrl.replace('/book/','/api/book/')))</js>",
"name": "name",
"author": "author",
"intro": "intro",
"tocUrl": "toc_url"

init 的返回值是对象时,后面的字段规则就在这个对象里按 JSONPath 取值;返回值是字符串时按普通规则走。

目录:ruleToc

"ruleToc": {
  "chapterList": "id.list@tag.dd",
  "chapterName": "tag.a@text",
  "chapterUrl": "tag.a@href",
  "isVip": "class.vip@text",
  "updateTime": "class.time@text",
  "nextTocUrl": "class.next@href"
}

列表规则与两个字段

和搜索一样:先切出"每一章",chapterName / chapterUrl 在单章里取。章节地址为空的那一条会被丢掉,所以分卷标题那种没有链接的行可以靠这个自然跳过 —— 除非你要把它们标成卷。

卷:isVolume

返回非空/真值时,这一条被当成卷名而不是章节(阅读页的目录会折叠成两层)。常写成 class.volume-title@text 或一段返回 true 的 JS。

目录是倒着排的

整条列表规则前面加 -:-id.list@tag.dd。这是最常见的一处修正 —— 有些站的目录从最新往回排。

下一页:nextTocUrl

返回空串 / 空数组 / null 就停止。可以是单个地址,也可以是地址数组(一次取多页)。常见的两种写法:

class.next@href
@js:(() => { const n = result.match(/\d+/); return n ? '/list/1_' + (+n[1]+1) + '.html' : '' })()

isVip / isPay

返回 null / false / 0 / 空串时视为非 VIP。标成 VIP 的章节会在目录里带上标记,但不拦阅读 —— 拦不拦由正文那一步决定。

formatJs 与 preUpdateJs

formatJs 在目录解析完之后执行,用来整体修正(比如统一章节名前缀);preUpdateJs 在"检查更新"之前跑。两个都很少用,先不写。
