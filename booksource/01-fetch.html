01 取数:java.ajax 与它的兄弟

先弄清一件事:在这个软件里所有出网都走应用自己的通道,不是浏览器的 fetch。所以规则里请一律用下面这几个方法,不要写 fetch()。

四个方法,一句话分工

  • java.ajax(url) —— 只想要正文文本时用它。返回值就是字符串。
  • java.get(url, headers) —— 想要响应对象(状态码、头、cookie)时用它。
  • java.post(url, body, headers) —— 表单或 JSON 提交。
  • java.head(url, headers) —— 只要响应头(测连通、取 etag)。

要文本,还是响应对象

java.ajax 给你一段文本,直接 JSON.parse 或丢给解析器就行。

var html = java.ajax('https://example.com/list?page=1');

需要看状态码或拿 cookie,就走 java.get,它返回的响应对象可以链式调用:

var res = java.get(url, {});
var code = res.code();
var body = res.body();
var ck   = res.cookies();

这些响应对象同时也可以直接当字符串用(await 或 String(...) 拿到的是正文),所以老写法不会因为换了方法就断。

URL 后面跟选项

java.ajax 认 "地址,{...}" 这种写法,后面那段 JSON 当作请求选项:

var opt = JSON.stringify({ headers: { 'X-Token': token }, method: 'GET' });
var text = java.ajax(base + url + ',' + opt);

这也是为什么错误信息里偶尔会看到整串地址 —— 解析失败了而已,先确认 JSON 拼对了。

不要做的事

  • 不要用 fetch()。它走浏览器直连,会被跨域拦住,表现是"请求没发出去",而且在我们这边看不到任何记录。
  • 不要在主解析规则里写同步忙等(while(Date.now()-t<n){})。软件对空转有预算,烧穿了这一趟会被中止。
  • 不要在 exploreUrl 里做重活。分类结果会缓存很久(15 天),求值慢会拖慢整个发现页。
