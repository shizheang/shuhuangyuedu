03 语法:先会这三条

走查里那几条规则已经够写出一个能跑的源了。这一页只把「够用」的部分说清楚 —— 默认规则怎么写、列表规则取哪一层、取值有哪些。剩下的(@js:、正则替换、&& / ||、@put:)用到再查 10 速查,现在不用记。

① 一条规则长什么样

规则串按 @ 分段:前面几段选节点,最后一段取值。每段是 类型.名称.位置。

class.book-list.0@tag.li@tag.a@href
└─ 选节点 ─────┘└─ 选节点 ─┘└ 取值 ┘
  • 类型有四种:class(按 class 找)、id(按 id 找)、tag(按标签找)、text(按包含的文字找);
  • 位置从 0 开始,不写就是全部;-1 是倒数第一个;
  • 取值写 @text(文字)、@html(内层 HTML)、@ownText(只取直属文字),或者任意属性名 @href / @src / @data-id。

就是这么回事 —— 走查里的 class.book-name@text 是「按 class 找到书名那个元素,取它的文字」,tag.h3@tag.a@href 是「先找 h3,再在它里面找 a,取 href」。

② 列表规则取的是「每一项」

这是整件事里最容易搞错的一处,也是走查里那个坑的来源。

列表规则(bookList / chapterList)要取每一本书 / 每一章的那个容器,不是整张列表。取对之后,后面几条字段规则都在单本 / 单章里跑,所以它们不用再写容器。

list  = "class.result-list@class.result-item"   ← 每一本
name  = "tag.h3@text"                          ← 在这本里取

两个判据可以自查:

  • 取到「整张列表」了 → 第一条数据的字段里会混进别的条目的内容(比如作者变成三个名字拼在一起)。多半是容器和每一项用了同一个标签名(都是 div),@tag.div 把容器自己也算成了一项。改用每一项独有的 class。
  • 取到「一本书」了 → 列表只有一条。多半是选择器写得太具体,匹配到了某个具体元素而不是每一项。

③ 相对地址不用自己补

@href 取到 book.html?id=1 这种相对地址时,软件会按来源页自动补成完整地址,封面同理。所以规则里直接写 @href 就行,不要自己拼域名 —— 拼了之后站点换域名就得改规则。

要写别的形式时

上面这套(默认规则)能应付大多数站。碰上这几种情况才需要换写法,都在 10 速查:

  • 页面返回的是 JSON 而不是 HTML → 用 $.data.list[*] 这类 JSONPath;
  • 站点的结构只有 CSS 选择器才写得出来 → 用 @css:;
  • 要按条件拼接、或结果要二次加工 → 用 @js:;
  • 取到的文字里带了要去掉的尾巴 → 用 ##正则##替换(走查里剥「作者：」用的就是它);
  • 一个字段有好几个备选位置 → 用 || 串起来。
