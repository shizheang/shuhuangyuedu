08 登录、凭据与加密

要登录的源分两种:地址型(给你一个网页,自己登)与 JS 型(软件弹一个输入面板,源脚本拿你填的值去换 token)。两者不会混用 —— 选错的话表现是"点了登录什么都不发生"。

地址型:只写 loginUrl

"loginUrl": "https://example.com/login"

软件会打开这个页面,你在里面登录(扫码、验证码、第三方都行),登录态按站点的规则存进本源的 cookie 夹。后续请求自动带上。

想让软件在登录后检查一下到底成没成,写 loginCheckJs:它拿到登录后的页面,抛错或返回值表示失败。

JS 型:再写 loginUi

"loginUi": "[{\"name\":\"账号\",\"type\":\"text\"},{\"name\":\"密码\",\"type\":\"password\"}]"

loginUi 是这个面板要问用户哪些字段。用户填完之后,值存在本源自己的登录信息里,规则里这样取:

java.getLoginInfo("账号")
java.getLoginInfoMap()["密码"]

拿到之后自己去换 token,再存回去给后面用:

var token = JSON.parse(java.post(url, "user=" + java.getLoginInfo("账号"))).token
java.putLoginInfo("token", token)

只还回本源是硬规则:源 A 读不到源 B 填的账号密码。真要借用,第一次会弹窗问用户一次,选择结果记在「设置 → 网络设置 → 访问」的放行清单里。

把凭据放进请求头

"header": "@js:(() => { var t = java.getLoginInfo('token')
  return JSON.stringify({ 'Authorization': 'Bearer ' + t }) })()"

header 写成 @js: 时每次请求都重新求值,所以 token 换掉也不用改源。getLoginHeader() / getLoginHeaderMap() 取的是登录时站点自己回的那组头。

加密

接口型站点常把参数签名或加密。常用的一批(都是同步的、纯计算):

方法说明
java.md5Encode(s)MD5 十六进制(32 位)
java.md5Encode16(s)MD5 取中间 16 位
java.sha256Hex(s)SHA-256 十六进制
java.digestHex(s, "SHA-1")指定摘要算法
java.HMacHex(data, "HmacSHA256", key)HMAC 十六进制,参数顺序是 (数据, 算法, 密钥)
java.base64Encode(s) / base64Decode(s)Base64 编 / 解
java.hexEncodeToString(bytes) / hexDecodeToString(s)十六进制编 / 解
java.strToBytes(s)字符串 → 字节数组(UTF-8)
java.encodeURI(s) / decodeURI(s)URL 编 / 解

对称加密不要拼成"一条龙",用工厂对象:

var c = java.createSymmetricCrypto("AES/ECB/PKCS5Padding", java.strToBytes(key))
c.encryptBase64(明文)      // 加密 → Base64
c.decryptStr(密文)

也有现成的快捷方法 java.aesEncodeToBase64String(data, key, transformation, iv) 这一族。密钥与 iv 既可以给字符串(按 UTF-8),也可以给字节数组 —— 站点给的是 32 字节密钥时,先 strToBytes 再传。

排查

  • 接口回"签名错误" → 先把拼出来的签名与浏览器里那份逐字比一遍(参数顺序、是不是少了一层 URL 编码);
  • 解密出来是乱码 → 十有八九是 iv / 模式传错,或者密钥被当成了字符串;
  • 用到手册里没有的方法 → 会当场抛错,不会静默返回 undefined。看 09 方法与边界 那张表。
