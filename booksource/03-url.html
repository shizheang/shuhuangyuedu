03 地址:GET、POST、请求头与翻页

搜索地址、发现地址、目录下一页地址,都是同一个写法:一个 URL,后面可以跟一段逗号开头的 JSON 选项。不写选项就是一个普通 GET。

形状

https://example.com/search?q={{key}}&page={{page}}
https://example.com/api/search,{"method":"POST","body":"kw={{key}}&page={{page}}","charset":"utf-8"}

分隔符是逗号后面紧跟 {。所以 ?a=1,b=2 这种 query 里的逗号不会被误切开。

选项能写什么

  • method —— POST / HEAD;不写或写别的都按 GET;
  • body —— 请求体。是字符串就原样发;不是字符串会先按 JSON 序列化;
  • headers —— 对象;写成 JSON 字符串也认(源仓库里 JSON.stringify({...}) 很常见);
  • charset —— 非 UTF-8 的站要写(如 gbk)。它同时决定**表单体**按哪种编码拼;
  • webView —— 非空时改用内置浏览器加载这一页(需要跑站点自己的 JS 才拿得到内容时用);
  • webViewDelayTime —— 用 webView 时再等多久(毫秒)才开始取;
  • retry —— 失败重试次数;
  • proxy —— 走代理,如 http://127.0.0.1:1080。

源的统一请求头 vs 单次请求的 header

书源顶层那个 header 字段对**该源的每一次请求**都生效;单次请求 JSON 里的 headers 只对那一次生效,并且会覆盖同名键。所以:

  • 站点固定要的 UA / Referer → 写进源顶层的 header;
  • 只有某个接口要的 X-Requested-With / 签名头 → 写在那一条地址的选项里。

{{key}} 与 {{page}}

在搜索 / 发现地址里,{{}} 只当 JS 求值。两个变量是预设的:key(搜索词)与 page(页码,从 1 开始)。

{{key}}                → 原样
{{java.encodeURI(key)}} → 先编码
{{(page-1)*20}}        → 偏移量式的分页
{{page-1 == 0 ? "" : page}} → 第一页不带页码

最后一行是常见需求:很多站的第一页地址里没有 page,而第二页开始才有。

相对地址谁来补

你不用拼。带 isUrl 语义的字段(书籍地址、封面、目录下一页、正文下一页)会按**当前页的地址**自动绝对化:/book/1 → https://example.com/book/1。只有真要换域名时才需要自己在 @js 里处理。

一次取多个地址

发现地址与目录下一页都支持数组(JSON 数组,或把多个地址用 && 连起来)。目录下一页的规则返回空串 / 空数组时就停止往后翻。
