03 凭据:登录信息与请求头

账号型站点几乎都是同一套:用户在登录面板填几个字段,规则里读出这些字段算出 token,再把 token 塞进请求头。不要把这些值硬编码进源 —— 它们按源存放,换台设备就该重新填。

登录面板是怎么来的

loginUi 字段声明面板上有哪些输入框和按钮;loginUrl 是进源前先跑的初始化(取站点地址、换取 token 这类)。用户在面板里填的东西会按源地址存下来,规则里再读。

loginUi（示例结构）
[
  { "name": "账号", "type": "text" },
  { "name": "密码", "type": "password" },
  { "name": "登录", "type": "button", "action": "Login()" }
]

规则里怎么读

  • source.getLoginInfoMap() —— 拿到整张表,.get('账号') 取值;
  • source.getLoginInfo('账号') —— 直接取一个字段;
  • source.putLoginHeader(字符串) —— 把算好的凭据写进"登录头",之后每次请求自动带上;
  • source.getLoginHeader() —— 读回这段登录头。

典型写法:面板按钮里算出 token 并写进登录头,正文规则什么都不用做。

function Login() {
  var ui = source.getLoginInfoMap();
  var token = java.post(base + '/login', JSON.stringify({
    user: ui.get('账号'), pass: ui.get('密码')
  })).body();
  source.putLoginHeader(JSON.stringify({ authorization: 'Bearer ' + JSON.parse(token).token }));
  java.toast('已登录');
}

静态请求头写在 header 字段

不带鉴权的固定头(UA、Referer)直接写成 JSON 字符串即可。写成 <js>…</js> 时会求值,用于算签名或时间戳。

{"User-Agent":"Mozilla/5.0 …","Referer":"https://example.com/"}

静态头与登录头会合并后随每次请求发出。

三条经验

  • 先确认面板里真有那个字段。规则读一个面板上没有的字段,拿到的是空串,而表现往往是"永远未登录",不报错。
  • 登录动作写在 loginUrl 里,别写在正文规则里。软件会在进源前跑一遍初始化,把登录产物准备好。
  • cookie 型站点可以用 cookie.getCookie(url) 同步读、cookie.setCookie(...) 写;但优先用登录头,它更可控。
