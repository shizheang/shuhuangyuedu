05 搜索与发现

这两段结构一模一样:一个列表规则先切出"每一项",再由一串字段规则在每一项里面取。九成的"搜不到"都出在第一步 —— 列表规则切错了层。

搜索

"searchUrl": "https://example.com/search?q={{key}}&page={{page}}",
"ruleSearch": {
  "bookList": "class.result-list@tag.li",
  "name": "tag.h3@text",
  "author": "class.author@text",
  "kind": "class.tag@text",
  "wordCount": "class.words@text",
  "lastChapter": "class.latest@text",
  "intro": "class.intro@text",
  "coverUrl": "tag.img@src",
  "bookUrl": "tag.a@href"
}

列表规则取的是「一个条目」

class.result-list@tag.li 的意思是"先找到结果列表这个容器,再取它下面的每一个 li",结果是一串条目。如果写成 tag.li,那是"页面上所有 li" —— 混进导航条、页脚,搜索页会出来一堆垃圾条目。

判断标准:列表规则取出来的第一个条目里,能单独取到书名和链接,就算切对了。

字段规则在「单个条目」里跑

所以字段规则不要再写容器:tag.h3@text 对,class.result-list.0@tag.h3@text 错(那样每一行都会取到第一条的数据)。

必填与选填

  • bookList / name / bookUrl —— 缺一不可;
  • author / kind / intro / coverUrl / wordCount / lastChapter / updateTime —— 取不到就是空,不影响搜索出结果;
  • checkKeyWord —— 用来判断"这一页是不是被站点换成了验证页/广告页",命中就丢弃。

发现

"exploreUrl": "玄幻::https://example.com/list/xuanhuan?page={{page}}\n都市::https://example.com/list/dushi?page={{page}}"

exploreUrl 每行一条分类,格式是 分类名::地址。分类名会出现在发现页的分类条里。

需要排版的写法

想给某个分类单独设宽度/换行时,可以写成 JSON 数组:

[
  {"title":"今日限免","url":"https://example.com/free?page={{page}}","style":{"layout_flexGrow":1}},
  {"title":"频道金榜","url":"https://example.com/rank?o={{ (page-1)*25 }}"}
]

style 里的 layout_flexGrow / layout_flexGrow / layout_wrapBefore 等键与发现页的布局一一对应;不写就自动排。

ruleExplore 与 ruleSearch 的区别

字段名几乎一样,但没有 checkKeyWord(发现页不是在搜关键词)。其余照抄搜索那段即可 —— 大部分站的列表页和搜索页是同一个模板。

什么时候发现页要用 @js

分类不是写死的,而是要先请求一个接口才拿得到(常见于 App 接口型站点)。这时 exploreUrl 整个写成 @js:,返回 名称::地址 拼成的多行字符串,或者上面那种 JSON 数组。

排错顺序

  1. 地址对不对 —— 调试页会显示实际请求的完整 URL(含 {{key}} / {{page}} 替换后的值);
  2. 响应是 HTML 还是 JSON —— 第一个字符是 < 还是 {;
  3. 列表规则切出来的条目数对不对(应该是"一页的条数",不是 0 也不是几百);
  4. 再看字段。字段空先把它换成 @html 看看那个节点里到底有什么。
