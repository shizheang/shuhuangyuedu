02 语法:一条规则从哪开始写

规则串的第一件事是**决定用哪种解析器**。前缀写了就用哪种,没写就看内容猜(以 $. 开头当 JSONPath、以 / 开头当 XPath、其余当默认规则)。选错不会报错,只会取到空 —— 而空和"这一页本来就没有"在界面上长得一样。

五种模式,靠前缀选

  • 默认规则(jsoup 风格)—— 不用写前缀,或者显式写 @@;
  • CSS —— 以 @css: 开头,后面接标准 CSS 选择器;
  • JSONPath —— 以 @Json: 开头,或直接以 $. / $[ 开头;
  • XPath —— 以 @XPath: 开头,或直接以 / / // 开头;
  • JS —— 以 @js: 开头,或整段写成 <js>…</js>。

默认规则怎么写

按 @ 分段,前一段选节点,最后一段取值。每段是 类型.名称.位置:

class.book-list.0@tag.li@tag.a@href
  • 类型:class / id / tag / text(按包含的文字找);
  • 位置从 0 开始,写 -1 就是倒数第一个;
  • 位置还能排除:!0:2 表示"排除第 0 与第 2 个";
  • children 取所有子标签,写法是 children[1]。

最后一段是取值:@text(文字)、@html(内层 HTML)、@ownText(只取直属文字,不含子标签里的)、@textNodes、@all(含标签本身),以及任意属性名:@href、@src、@data-id。

CSS 与 XPath

@css:.book-list li a@href
@XPath://div[@id='content']//p//text()

两种都是标准写法,能用在网上搜到的现成选择器。CSS 后面同样可以用 @ 继续取值;XPath 一般直接取到文本(//text())或属性(//@href)。

JSONPath

$.data.list[*]      → 列表:取数组里的每一项
$.data.list[0].title → 单个字段
$..title            → 任意层级的 title

列表规则取的是"每一项":$.data.list[*] 得到的是一串条目,后面每条字段规则都在**单个条目**里跑,所以字段只写 $.title。

JS:@js: 与 <js>

@js: 只能放在**最后一段**;要拿前面规则的结果,用变量 result。整段 JS 里**最后一条产生值的语句**就是规则结果。

@js:result.split('\n').filter(x => x.trim()).join('\n')

<js>…</js> 可以放在任意位置,还能当分隔符用:tag.li<js></js>//a。

正则替换:##正则##替换

跟在别的规则后面,把结果里的匹配项**循环**替换掉。第二段留空就是删除:

id.content@html##<br\s*/?>##\n

三个连接符

只用于同一类规则之间(不跨 JS 与正则):

  • && —— 全部取到并合并;
  • || —— 取第一个有结果的(最常用:一个字段好几个备选位置);
  • %% —— 依次交错取:三个列表的 1、2、3 各取第一个,再取第二个……

把中间结果存起来:@put: 与 @get:

同一个请求要复用几次时就别取三遍:

https://api.example.com/view?aid={{$.id}}@put:{"cid":"$.cid"}

@put: 把后面几个子规则的结果存进变量表,后面的规则用 @get:{cid} 取。它在**同一次请求的那条规则链**里有效。

在规则里插值:{{}}

在搜索地址 / 发现地址里,{{}} 里只当 JS 写({{key}}、{{page}}、{{(page-1)*20}});在**其它位置**的 {{}} 里可以写任意规则,但要带类型前缀({{@@class.x@text}}、{{$.title}})。

列表反序

整条列表规则前面加一个 - 就把顺序倒过来 —— 有些站的目录是倒着排的:

-id.list@tag.dd
